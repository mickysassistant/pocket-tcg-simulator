## Confirmed Bugs (Previously Reported)

### 🔴 BUG-002: EX Pokemon Always Award 1 Point Instead of 2
**Status:** 🔴 CONFIRMED (STILL PRESENT)
**Severity:** HIGH
**File:** `js/engine/game-state.js` line 702

**Issue:** `handleKOPokemon` checks `pokemon.cardId.includes('ex')` but card IDs like "A1-004" never contain "ex". Only card names have "ex" suffix.

**Impact:** EX Pokemon only award 1 point instead of 2, breaking competitive scoring.

---

### 🟡 BUG-003: Bench Null Slots After KO Block New Plays
**Status:** 🔴 CONFIRMED (STILL PRESENT)
**Severity:** MEDIUM
**File:** `js/engine/game-state.js` line 690, `js/engine/moves.js` line 71

**Issue:** `handleKOPokemon` sets `player.bench[index] = null` but doesn't filter nulls. `canPlayToBench` counts null slots via `player.bench.length >= MAX_BENCH`.

**Impact:** Players cannot play new Pokemon to bench after bench KO, even with fewer than 3 real Pokemon.

## NEW Bugs Discovered (2026-02-11)

### 🔴 BUG-007: executeAttack Does Not Validate Energy Cost
**Status:** 🔴 NEW BUG CONFIRMED
**Severity:** HIGH
**Files:** `js/engine/game-state.js` line 886, `js/main.js` (handleAttackClick)

**Issue:** `executeAttack` does NOT call `canAttack` or validate energy before execution. `canAttack` exists with `hasEnoughEnergy` check but is never used.

**Root Cause:**
```javascript
// js/main.js - handleAttackClick
function handleAttackClick(attackIndex) {
    // ... validation checks ...
    
    // Execute attack WITHOUT energy validation
    state = executeAttack(state, attackIndex, getCard); // ❌ NO ENERGY CHECK
    render(state);
}
```

**Expected:** Attack should fail if insufficient energy.

**Actual:** Attack executes successfully regardless of energy cost.

**Impact:** Players can attack with zero or insufficient energy, breaking fundamental game rules.

**Fix:**
```javascript
// In handleAttackClick, before executeAttack:
const canAttackResult = canAttack(state, attackIndex, getCard);
if (!canAttackResult) {
    logError(t('alerts.notEnoughEnergy'));
    return;
}
state = executeAttack(state, attackIndex, getCard);
```

### 🔴 BUG-008: canEvolve Does Not Validate evolvesFrom Relationship
**Status:** 🔴 NEW BUG CONFIRMED
**Severity:** HIGH
**File:** `js/engine/moves.js` line 113

**Issue:** `canEvolve` validates turn rules but NOT evolution validity. Allows evolving any Pokemon with any card.

**Root Cause:**
```javascript
// js/engine/moves.js - canEvolve
export function canEvolve(state, playerId, handIndex, targetLocation) {
    // Validates turn <= 1 ❌
    // Validates target exists ❌
    // Validates turnPlayed !== currentTurn ❌
    // Validates lastEvolved !== currentTurn ❌
    
    // MISSING: Validates that handCard.evolvesFrom === targetCard.name ❌
    
    return { valid: true };
}
```

**Comment in executeEvolve says:** "caller should have verified evolvesFrom" - but this never happens.

**Expected:** Should only allow valid evolution chains (Bulbasaur → Ivysaur → Venusaur).

**Actual:** Can evolve Bulbasaur with Charmeleon card.

**Impact:** Breaks evolution mechanics completely.

**Fix:**
```javascript
// In canEvolve, add getCardFn parameter and validate:
const handCardData = getCardFn(p.hand[handIndex]);
const targetCardData = getCardFn(target.cardId);
if (!handCardData.evolvesFrom?.includes(targetCardData.name)) {
    return { valid: false, reasonKey: 'errors.validation.invalidEvolution' };
}
```

### 🟡 BUG-009: canAttack Does Not Validate PARALYSIS or SLEEP Status
**Status:** 🔴 NEW BUG CONFIRMED
**Severity:** MEDIUM
**File:** `js/engine/game-state.js` line 992

**Issue:** `canAttack` only validates existence + energy, ignores PARALYSIS/SLEEP status.

**Root Cause:**
```javascript
// js/engine/game-state.js - canAttack
export function canAttack(state, attackIndex, getCardFn) {
    // Validates attacker exists ❌
    // Validates attackerCard exists ❌
    // Validates attack exists ❌
    // Validates energy cost ❌
    
    // MISSING: Check PARALYSIS/SLEEP status ❌
    
    return hasEnoughEnergy(attacker.energy, attack.energyCost);
}
```

**Note:** `canRetreat` correctly validates PARALYSIS/SLEEP, but `canAttack` does not.

**Expected:** Pokemon with PARALYSIS or SLEEP cannot attack.

**Actual:** Attack succeeds despite PARALYSIS/SLEEP status.

**Impact:** Players can attack with incapacitated Pokemon, bypassing core status rules.

**Fix:**
```javascript
// In canAttack, add status check:
if (attacker.status === STATUS.PARALYSIS) return false;
if (attacker.status === STATUS.SLEEP) return false;
```
