## Confirmed Bugs

### 🔴 BUG-002: EX Pokemon Always Award 1 Point Instead of 2
**Severity:** HIGH
**Priority:** HIGH
**Status:** CONFIRMED
**File:** `js/engine/game-state.js` line 700

**Description:**
EX Pokemon should award 2 points when KO'd, but currently only award 1 point. The bug occurs because `handleKOPokemon` attempts to detect EX cards by checking if `pokemon.cardId` contains "ex", but card IDs (e.g., "A1-004") never contain this text. Only card names contain "ex" (e.g., "Venusaur ex").

**Root Cause:**
```javascript
// js/engine/game-state.js line 700
const isEX = pokemon.cardId.includes('ex') || pokemon.cardId.includes('EX');
```

The `Pokemon` state object only stores `cardId`, not the card name or rules. To properly detect EX cards, the function would need to:
1. Accept a `getCardFn` parameter to fetch card data
2. Call `getCardFn(pokemon.cardId)` to get the full card object
3. Check either `card.name.includes(' ex')` or `card.rules.some(r => r.label === 'ex')`

**Expected Behavior:**
When an EX Pokemon is KO'd, opponent receives 2 points:
```
KO'd opponent's Venusaur ex, +2 points
```

**Actual Behavior:**
When an EX Pokemon is KO'd, opponent receives only 1 point:
```
KO'd opponent's Venusaur ex, +1 points  // WRONG
```

**Steps to Reproduce:**
1. Set up a game with player1 having Venusaur ex as active Pokemon
2. Have player2 attack and KO Venusaur ex
3. Check player2's points
4. Expected: 2 points
5. Actual: 1 point

**Impact:** HIGH - Affects scoring, critical for competitive play. Players won't get proper rewards for KOing high-value EX cards.

**Recommended Fix:**
1. Modify `handleKOPokemon` signature to accept `getCardFn`
2. Update all call sites to pass `getCardFn`:
   - `executeCheckup` (lines 549, 571)
   - `executeAttack` (line 956)
   - `processTurnEnd` (line 1498)
3. Use `getCardFn` to fetch card data and detect EX:
   ```javascript
   const card = getCardFn(pokemon.cardId);
   const isEX = card.name.includes(' ex') || card.rules?.some(r => r.label === 'ex');
   ```

### 🟡 BUG-003: Bench Null Slots After KO Block New Plays
**Severity:** MEDIUM
**Priority:** MEDIUM
**Status:** CONFIRMED
**File:** `js/engine/game-state.js` line 690, `js/engine/moves.js` line 71

**Description:**
When a bench Pokemon is KO'd during Pokemon Checkup, `handleKOPokemon` sets `player.bench[index] = null` but doesn't remove the null from the array. The validation function `canPlayToBench` checks `player.bench.length >= MAX_BENCH`, which counts null slots. This means after a bench KO, players cannot play new Basic Pokemon to the bench even though they have fewer than 3 actual Pokemon.

**Root Cause:**
```javascript
// js/engine/game-state.js line 690
player.bench[index] = null;

// js/engine/moves.js line 71
if (player.bench.length >= MAX_BENCH) return { valid: false, reasonKey: 'errors.validation.benchFull' };
```

**Expected Behavior:**
After a bench Pokemon is KO'd:
- `player.bench` should contain only non-null Pokemon objects
- Player should be able to play new Basic Pokemon until bench has 3 real Pokemon
- Validation should count only non-null entries

**Actual Behavior:**
After a bench Pokemon is KO'd:
- `player.bench` contains null entries
- `player.bench.length` remains 3 even with only 2 real Pokemon
- "Bench full" error when trying to play a new Pokemon

**Steps to Reproduce:**
1. Set up a game with player1 having 3 bench Pokemon
2. Apply poison or burn to one bench Pokemon
3. End turn to trigger Pokemon Checkup
4. Bench Pokemon dies from poison/burn damage
5. Try to play a new Basic Pokemon from hand to bench
6. Expected: Success (only 2 Pokemon remain)
7. Actual: "Bench full" error

**Impact:** MEDIUM - Blocks gameplay after bench KO. Players are unable to recover bench positions, which is a core mechanic.

**Recommended Fix:**
Option A: Filter nulls after KO (preferred - cleaner array)
```javascript
// In handleKOPokemon, after setting to null:
player.bench = player.bench.filter(p => p !== null);
```

Option B: Count non-nulls in validation
```javascript
// In canPlayToBench:
const nonNullCount = player.bench.filter(p => p !== null).length;
if (nonNullCount >= MAX_BENCH) return { valid: false, ... };
```

### 🟡 BUG-004: Confusion Status Not Implemented in Game Logic
**Severity:** MEDIUM
**Priority:** LOW
**Status:** CONFIRMED
**Files:** `js/engine/game-state.js`, `js/engine/constants.js`

**Description:**
Confusion status is defined in constants and available in the UI edit modal, but is never handled in game logic. In Pokemon TCG Pocket, Confusion should:
- **Pokemon Checkup:** Coin flip - heads = cure, tails = remain confused
- **Attack:** Coin flip - heads = attack proceeds, tails = deal 20 damage to self instead

**Root Cause:**
1. `STATUS.CONFUSION` is defined but not in `STATUS_CHECKUP_ORDER`
2. `processCheckupForPokemon` has no case for confusion
3. `executeAttack` has no pre-attack confusion check

**Expected Behavior:**
When a Pokemon has confusion status:
- During Pokemon Checkup: Coin flip to determine if cured
- During attack: Coin flip - tails = 20 self-damage

**Actual Behavior:**
Confusion status is set but has no effect:
- No checkup processing (status persists indefinitely)
- No self-damage on attack tails

**Steps to Reproduce:**
1. Enter edit mode
2. Set a Pokemon's status to "confusion"
3. End turn to trigger Pokemon Checkup
4. Expected: Coin flip for cure
5. Actual: No effect, status persists
6. Attack with confused Pokemon
7. Expected: Coin flip for self-damage
8. Actual: Attack proceeds normally

**Impact:** LOW - Feature not yet implemented, but confusion status is accessible in UI which creates user confusion (pun intended).

**Recommended Fix:**
1. Add `STATUS.CONFUSION` to `STATUS_CHECKUP_ORDER` in constants.js
2. Add confusion case in `processCheckupForPokemon`:
   ```javascript
   case STATUS.CONFUSION:
     const flip = result.coinQueue.shift();
     if (flip) {
       pokemon.status = null; // Cured
       details += ' [Confused → Cured]';
     }
     break;
   ```
3. Add pre-attack confusion check in `executeAttack`:
   ```javascript
   // Before executing attack
   if (attacker.status === STATUS.CONFUSION) {
     const flip = newState.coinQueue.shift();
     if (!flip) {
       // Tails: self-damage
       attacker.currentHp -= 20;
       newState.log.push({ action: 'confusion-damage', ... });
       return newState;
     }
   }
   ```

### 🟢 BUG-005: checkWinCondition Doesn't Check "No Pokemon Left"
**Severity:** LOW
**Priority:** LOW
**Status:** CONFIRMED
**File:** `js/engine/game-state.js`

**Description:**
`checkWinCondition` only checks points and turn limit. The "opponent has no Pokemon left" win condition is handled separately in the KO flow. If a state is loaded where a player has no active and no bench, `checkWinCondition` won't detect a winner.

**Expected Behavior:**
When a player has no Pokemon (active is null AND bench is all nulls/empty):
- `checkWinCondition` should return opponent as winner

**Actual Behavior:**
`checkWinCondition` only checks:
- Player with 3+ points wins
- Turn limit (turn 30): player with more points wins
- Does not check "no Pokemon left" condition

**Steps to Reproduce:**
1. Create a scenario where player1 has no active and empty bench
2. Call `checkWinCondition(state)`
3. Expected: Returns 'player2' (opponent wins)
4. Actual: Returns null (no winner)

**Impact:** LOW - Edge case. Unlikely to occur in normal gameplay because:
- The KO flow handles "no Pokemon" by ending the game immediately
- Players would need to manually edit state to create this situation

**Recommended Fix:**
Add "no Pokemon" check to `checkWinCondition`:
```javascript
// Check "no Pokemon left" win condition
const p1HasPokemon = player1.active || player1.bench.some(p => p !== null);
const p2HasPokemon = player2.active || player2.bench.some(p => p !== null);

if (!p1HasPokemon && !p2HasPokemon) {
  return 'tie'; // Both have no Pokemon
}
if (!p1HasPokemon) {
  return 'player2';
}
if (!p2HasPokemon) {
  return 'player1';
}
```

### 🟢 BUG-006: Evolution HP Handling May Be Incorrect
**Severity:** LOW
**Priority:** LOW
**Status:** DOCUMENTED GAP
**File:** `js/engine/moves.js` line 259

**Description:**
`executeEvolve` uses `Math.min(target.currentHp, evoCardData.hp)` which keeps currentHp capped to new max HP. In Pokemon TCG, evolution should preserve **damage counters**, meaning: `newHp = newMaxHp - (oldMaxHp - oldCurrentHp)`. Current code doesn't know oldMaxHp so can't calculate this correctly.

**Example:**
- Bulbasaur: 70 max HP, 40 current HP (30 damage)
- Evolves to Ivysaur: 90 max HP
- Expected: 90 - 30 = 60 HP (damage counters preserved)
- Actual: min(40, 90) = 40 HP (damage lost)

**Impact:** LOW - Requires access to card data (oldMaxHp) which isn't currently stored in Pokemon state.

**Recommended Fix:**
Store `maxHp` in Pokemon state:
```javascript
export function createPokemon(cardId, turnPlayed = 0) {
  const card = getCardFn(cardId);
  return {
    cardId,
    maxHp: card.hp,  // Store max HP
    currentHp: card.hp,
    // ...
  };
}

// In executeEvolve:
const oldMaxHp = target.maxHp || target.currentHp;
const damage = oldMaxHp - target.currentHp;
target.maxHp = evoCardData.hp;
target.currentHp = evoCardData.hp - damage;
```
