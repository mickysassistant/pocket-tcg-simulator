## Codebase Patterns
- The project uses node:test for testing, run with `node --test tests/**/*.test.js`
- Tests are defined inline with custom runTest helper for custom error formatting
- Database persistence uses SQLite with node:sqlite DatabaseSync (synchronous API)
- Each DB operation creates its own connection and closes it in finally block
- GameState is the core game state object that manages players, turn tracking, etc.
- TurnManager.startTurn(playerId) handles turn start including auto-draw of 1 card
- Game state can be persisted to SQLite with state.save() and restored with GameState.fromJSON()
- CLI commands are in src/cli/commands/ and use a handler(argv) async function
- The argv object contains: json, help, positionalArgs, and formatOutput helper
- Actions are registered in src/cli/services/actions.js with schemas for validation
- Sessions and state are managed through repositories in src/cli/services/
- Action validation returns { valid, reason?, errors? } object
- CLI output supports both plain text and JSON formats via --json flag
- TurnManager.endTurn() returns win condition result or null if game continues
- Session status can be updated via sessions.update(sessionId, { status: 'completed' })
