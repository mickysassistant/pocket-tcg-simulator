## Codebase Patterns

- Pure JS (no build), Node.js. Tests run with: `node <test-file>`
- TEST_CMD: `for test in tests/rules/*.test.js tests/rule-lock-manifest.test.js tests/integration/regression-suite.test.js; do node "$test" || exit 1; done`
- All systems follow the pattern: `new XyzSystem(gameState)` and are wired in `src/index.js`
- `createGame()` in `src/index.js` returns a single object with all system instances
- Tests use a simple `runTest(name, fn)` pattern with custom assert helpers (no external test runner)
- Game state uses `players.player1/player2` with fields: `deck`, `hand`, `banque`, `activePokemon`, `energyZone`
- `activePokemon` is a single object; `banque` is an array of Pokémon objects
- Each Pokémon object has: `id`, `name`, `type`, `hp`, `energy` (array), `playedThisTurn`, etc.
- AbilitySystem: abilities are keyed as `"playerId:pokemonId"` in a Map
- KO-triggered effects are handled via KoTriggerSystem and invoked from AttackSystem when isKO=true
- All system events (attacks, abilities, KO triggers) are logged to `gameState.turnLog` with a `type` field
